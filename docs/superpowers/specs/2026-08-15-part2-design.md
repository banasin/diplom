# Спецификация реализации: Часть 2

**Дата:** 2026-08-15
**Проект:** Предсказание аффинности аптамер–мишень. Часть 2 — расширение на
разнородные мишени и механизмы взаимодействия.
**Основа:** Часть 1 завершена (two-tower для пар «аптамер–белок», честный сплит,
ESM-2 эмбеддинги, XGBoost-бейзлайн). Часть 2 переиспользует её модули.

## Контекст и цель

Ввести второй тип мишеней — **малые молекулы** — и объединить разнородные
мишени (белки + молекулы) в общем предсказательном пространстве одной модели;
сравнить механизмы слияния представлений аптамера и мишени.

Данные молекул: `data/dataset_smallmol.parquet` (531 измерение / 496 пар /
132 мишени / 427 аптамеров; 90% с PubChem CID; 57% значений оговорённые).

## Гипотезы

- **H3 (унификация):** единая модель, обученная совместно на белках и молекулах
  в общем предсказательном пространстве, предсказывает аффинность по каждому типу
  мишеней не хуже отдельных по-типных моделей — за счёт переноса представлений
  (общая башня аптамера); ожидаемая выгода наибольшая для малых молекул (мало
  данных).
- **H4 (слияние):** обучаемое взаимодействие представлений (билинейное или
  cross-attention) точнее простой конкатенации.

## Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Объём | Обе цели: унификация разнородных мишеней + сравнение слияний |
| Кодирование молекул | ChemBERTa (предобученный энкодер, mean-pooling), аналог ESM-2 |
| Источник SMILES | PubChem PUG REST по CID, с кэшем |
| Механизмы слияния | concat, bilinear, cross-attention |
| Оговорённые значения | Оставляем для ОБОИХ типов в Части 2 (единое правило, максимум данных) — осознанное отличие от Части 1 |
| Cross-attention | M=16 «токенов» на мишень (chunk-pooling пер-токенных выходов) |
| Разбиение | Честный сплит по кластерам аптамеров на объединённых данных + случайный |
| Компьют | Windows, RTX 4070 12 ГБ (CUDA) |

## Модульная структура

Переиспускаемое из Части 1: `src/features/aptamer.py`, `src/data/cluster.py`,
`src/evaluation/metrics.py`, `src/features/protein.py` (ESM-2),
`src/features/protein_seqs.py`, части `src/data/split.py`, `src/config.py`.

### 1. Данные и целевая переменная (расширение `src/data/split.py`)

- `build_pairs` расширяется/дополняется вариантом, который **НЕ отбрасывает**
  оговорённые (`qualified_any`), а оставляет их — для обоих типов мишеней в
  Части 2. Медиана log-Kd по уникальной паре сохраняется.
- Функция построения **объединённой** таблицы пар: белки + молекулы с колонкой
  `target_type ∈ {"protein", "molecule"}` и единым `target_key`
  (UniProt ID для белков, PubChem CID для молекул).
- Кластеризация и сплит (`assign_clusters`, `make_splits`,
  `assert_no_cluster_leakage`, `check_split_balance`) применяются к объединённым
  парам без изменений (кластеризация по последовательности аптамера).

### 2. `src/features/molecule_smiles.py` — SMILES из PubChem

- `parse_cid(target_cid) -> int|None` — разбор строки вида `"CID 12345"`.
- `fetch_smiles(cid) -> str|None` — GET PubChem PUG REST
  `.../compound/cid/{cid}/property/CanonicalSMILES/TXT`; `None` при ошибке.
- `load_smiles(cids, cache_path) -> dict[str,str]` — кэширующая обёртка (JSON в
  `data/`, вне git), тянет только отсутствующее. Ключ — исходный `target_key`.

### 3. `src/features/molecule.py` — ChemBERTa эмбеддинги

- `embed_molecules(smiles, model_name, cache_path, batch_size) ->
  dict[str,np.ndarray]` — mean-pooled эмбеддинг ChemBERTa (аналог `protein.py`),
  кэш `.npz` (вне git), атомарная запись, эмбеддинг раз на молекулу.
- `token_reps(...)` (или параметр) — дополнительно M=16 «токенов» на молекулу
  (chunk-pooling пер-токенных выходов), для cross-attention.
- Модель ChemBERTa фиксируется в конфиге (напр. `DeepChem/ChemBERTa-77M-MLM`);
  размерность выясняется из модели и не хардкодится.
- **Симметрично** для белков: `src/features/protein.py` дополняется получением
  M=16 токенов из пер-остаточных ESM-2 (chunk-pooling), для cross-attention;
  существующий mean-pooled путь сохраняется.

### 4. `src/features/assemble.py` — объединённая сборка

- Расширение: собрать признаки для объединённых пар, маршрутизируя мишень по
  `target_type` к нужному словарю эмбеддингов (белок/молекула). Так как
  размерности эмбеддингов разнятся по типам, таблица признаков хранит:
  аптамерные признаки, тип мишени, и по-типные эмбеддинги (pooled и M-токенные),
  выровненные по строкам; проекция в общую размерность D — внутри модели.
- Пары без эмбеддинга мишени отбрасываются (как в Части 1); число отброшенных
  логируется.

### 5. `src/models/fusion.py` — модули слияния

- `ConcatFusion(a_dim, t_dim) ` — конкатенация → далее голова.
- `BilinearFusion(a_dim, t_dim, out)` — `nn.Bilinear` (или факторизованное).
- `CrossAttentionFusion(dim, heads, ...)` — multihead cross-attention между
  токенами аптамера и M-токенами мишени → пулинг.
- Единый интерфейс `forward(...) -> вектор` для головы; выбор по имени из конфига.

### 6. `src/models/unified.py` — единая сеть

- Общая башня аптамера (k-меры → эмбеддинг; для cross-attention — токенная ветвь
  через 1D-свёртку по последовательности).
- Тип-специфичная проекция мишени в общую размерность D + обучаемый эмбеддинг
  типа мишени.
- Сменный модуль слияния (из `fusion.py`) → MLP-голова → log-Kd.
- Обучение совместное на объединённых парах: MSE, стандартизация цели по train,
  ранняя остановка, фиксированный seed (как в Части 1). Маршрутизация по типу
  внутри батча (проекция по типам, затем объединение).

### 7. `src/run_part2.py` — оркестратор

- Строит объединённые пары → сплит (кластерный + случайный) → признаки
  (ESM-2 белков, ChemBERTa молекул, оба + M-токены) → обучает:
  - единую модель с каждым из трёх слияний (H4);
  - отдельные по-типные модели two-tower (белки-only, молекулы-only) — для H3;
  - ссылочный XGBoost **по каждому типу отдельно** (белки на ESM-2, молекулы на
    ChemBERTa) — планка качества; единый XGBoost по разнородным мишеням не
    строим (несовместимые размерности признаков).
- Метрики **по типам и общие** на кластерном и случайном сплите; таблицы в
  `results/metrics/part2_metrics.csv`, графики в `results/figures/`.
- **H3:** по-типные метрики единой модели vs отдельные по-типные модели.
- **H4:** три слияния между собой.

## Поток данных

```
dataset_protein.parquet ─┐
dataset_smallmol.parquet ─┴─ build_unified_pairs (qualified оставлены)
   └─ cluster+split (по аптамеру) ─► объединённая таблица + метки сплита
белки:   protein.py  (ESM-2, pooled + M-токены)
молекулы: molecule_smiles.py→molecule.py (ChemBERTa, pooled + M-токены)
   └─ assemble (маршрут по target_type) ─► признаки
       ├─ unified.py × {concat, bilinear, cross-attention}  (H4)
       ├─ two-tower по-типно (белки / молекулы)              (H3)
       └─ XGBoost (ссылка)
   └─ metrics (по типам и общие) ─► таблицы + графики
```

## Конфигурация

Расширение `configs/`: `part2.yaml` с seed, порогом кластеризации, долей теста,
именем ChemBERTa-модели, числом токенов M, гиперпараметрами слияний и обучения.

## Тестирование

- Юнит-тесты: `parse_cid`; `load_smiles` (кэш без сети); `embed_molecules`
  (форма, детерминизм из кэша, на крошечной ChemBERTa или мок-токенайзере);
  модули слияния (формы выходов на синтетике; cross-attention с M-токенами);
  единая сеть (переобучение крошечного батча со смешанными типами мишеней).
- Инвариант анти-утечки и guard баланса — на объединённых данных.
- Детерминизм при фиксированном seed.
