# Спецификация реализации: Часть 1, задачи 2–6

**Дата:** 2026-08-15
**Проект:** Предсказание аффинности аптамер–белок (two-tower), Часть 1.
**Область:** реализация задач 2–6 плана (`plan_diploma.md`). Задача 1 (чистка
данных, `src/data/clean.py`) уже выполнена.

## Контекст и цель

На входе — очищенный набор пар «аптамер–белок» `data/dataset_protein.parquet`
(1713 измерений / 1601 уникальная пара / 1546 аптамеров / 414 мишеней, 89% с
UniProt ID). Нужно построить воспроизводимый контур предсказания log-Kd и
проверить две гипотезы:

- **H1:** two-tower нейросеть точнее классического бейзлайна на данных,
  разбитых по сходству последовательностей.
- **H2:** кластерное разбиение даёт более консервативную оценку, чем случайное.

## Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Кластеризация аптамеров | Python-аналог CD-HIT (жадный по идентичности), Windows-native, без внешних зависимостей |
| Эмбеддинги белков | ESM-2 650M (`esm2_t33_650M_UR50D`), mean-pooling → 1280-мерный вектор |
| Целевая переменная | Медиана log-Kd по уникальной паре; оговорённые (`qualified_any=True`) отбрасываются |
| Протокол оценки | Фиксированный split: кластерный + случайный, оба отчётные |
| Бейзлайн | XGBoost |
| Сеть | PyTorch, two-tower с конкатенацией (без билинейных/attention-слияний) |
| Компьют | Windows, NVIDIA RTX 4070 12 ГБ (CUDA) |

## Модульная структура

Границы модулей соответствуют задачам плана. Каждый модуль имеет одну
ответственность, чётко определённый вход/выход и тестируется независимо.

### 1. `src/data/split.py` — Задача 2 (честное разбиение)

**Ответственность:** превратить очищенный набор в фиксированную таблицу пар с
метками разбиений.

- **Построение цели:**
  1. Отбросить записи с `qualified_any == True`.
  2. Схлопнуть в одну строку на уникальную пару `(aptamer_seq, aptamer_type,
     target_key)` с медианой `log_Kd` по измерениям.
  3. Результат — фиксированный вход для всех моделей.
- **Кластеризация:** жадный алгоритм в стиле CD-HIT на уникальных
  последовательностях аптамеров:
  - нормализация `U→T` перед сравнением (ДНК/РНК-гомологи не должны утекать
    между train/test);
  - сортировка по убыванию длины; каждую последовательность либо приклеиваем к
    существующему кластеру-представителю при идентичности ≥ порога, либо заводим
    новый кластер;
  - порог идентичности (`identity_threshold`, аналог `-c` в CD-HIT) — параметр,
    старт `0.8`;
  - идентичность считается глобальным попарным выравниванием
    (Needleman–Wunsch, доля совпавших позиций) с k-мерным префильтром: пары с
    низким k-мерным сходством пропускаются без выравнивания для ускорения. На
    1546 коротких последовательностях это дёшево.
- **Разбиения (доля `test_size`, старт 0.2, фиксированный `seed`):**
  - **кластерное:** все пары одного аптамерного кластера целиком в train **или**
    в test (группировка по кластеру);
  - **случайное:** по парам, та же доля.
- **Инвариант анти-утечки:** ни один аптамерный кластер не пересекает границу
  train/test в кластерном разбиении (проверяется в коде и в тестах).
- **Выход:** таблица `(aptamer_seq, aptamer_type, target_key, log_Kd,
  cluster_id, split_cluster, split_random)` + краткий отчёт (число кластеров,
  распределение размеров, счётчики train/test). Артефакт в `data/`
  (вне git; воспроизводим из кода и seed).

### 2. `src/features/aptamer.py` — Задача 3a (кодирование аптамеров)

**Ответственность:** превратить последовательность аптамера в числовой вектор.

- Вектор частот **k-меров** над алфавитом `ACGT` (с нормализацией `U→T`);
  `k` — параметр (старт 3–4), размерность `4^k`.
- Дополнительные признаки: флаг DNA/RNA, длина последовательности.
- Согласовано с текущей N-граммной моделью.
- Один и тот же вектор используется и в бейзлайне, и в аптамерной башне сети —
  для честного сравнения.

### 3. `src/features/protein.py` — Задача 3b (эмбеддинги белков)

**Ответственность:** получить фиксированный вектор представления белка-мишени.

- Скачивание белковых последовательностей из **UniProt** по `target_id`
  (кэш в `data/`, вне git). Мишени без UniProt ID (~11%) для Части 1
  отбрасываются; факт и число фиксируются в отчёте.
- **ESM-2 650M** (`esm2_t33_650M_UR50D`): mean-pooling скрытых представлений
  последнего слоя по остаткам → 1280-мерный вектор на белок.
- Инференс батчами на GPU; последовательности длиннее лимита модели (>1022
  токенов) усекаются.
- Кэш эмбеддингов (`.npy`/`.pt`, вне git), считается один раз.

### 4. `src/models/baseline.py` — Задача 4 (бейзлайн)

**Ответственность:** планка качества.

- **XGBoost**-регрессия на конкатенации признаков
  `[k-меры аптамера | ESM-2 белка | флаги]`.
- Обучение на train, предсказание на test — независимо для кластерного и
  случайного разбиений. Гиперпараметры — из конфига.

### 5. `src/models/twotower.py` — Задача 5 (two-tower сеть)

**Ответственность:** обучаемая нейросетевая модель.

- PyTorch. **Башня аптамера:** MLP(k-меры → скрытое → эмбеддинг).
  **Башня белка:** MLP(1280 → скрытое → эмбеддинг).
- **Слияние:** конкатенация эмбеддингов → MLP-голова → скаляр log-Kd.
  Усложнённые слияния (билинейное, cross-attention) — вне области (Часть 2).
- Функция потерь MSE; стандартизация цели по статистикам train; ранняя
  остановка на валидационном срезе из train; фиксированный seed.

### 6. `src/evaluation/metrics.py` — Задача 6 (оценка)

**Ответственность:** единый протокол оценки и сравнение гипотез.

- Метрики: **RMSE, MAE, Pearson r, Spearman ρ, R²** — один код для бейзлайна и
  сети.
- **H1:** сеть vs бейзлайн на кластерном разбиении.
- **H2:** кластерное vs случайное разбиение для обеих моделей.
- Выход: таблицы метрик (`results/metrics/`, вне git) и графики pred-vs-true
  (`results/figures/`, вне git).

## Поток данных

```
dataset_protein.parquet
   └─ split.py ─────────────► таблица пар + метки (cluster_id, split_cluster, split_random)
aptamer.py (k-меры) ─────────┐
protein.py (UniProt → ESM-2) ─┴─► матрицы признаков train/test
   ├─ baseline.py (XGBoost) ──┐
   └─ twotower.py (PyTorch) ──┴─► metrics.py ─► таблицы + графики
```

## Конфигурация и оркестрация

- `configs/part1.yaml`: `seed`, `identity_threshold`, `test_size`, `k`,
  имя ESM-модели, гиперпараметры XGBoost и сети.
- Запускаемый оркестратор `src/run_part1.py` прогоняет пайплайн end-to-end;
  тяжёлые артефакты (UniProt-последовательности, ESM-2 эмбеддинги, метрики)
  кэшируются и переиспользуются.

## Тестирование

- **Юнит-тесты:**
  - кластеризация: маленький набор последовательностей → ожидаемые кластеры;
  - k-мер-векторизатор: известная строка → известные счётчики (включая U→T);
  - метрики: известные массивы → известные значения.
- **Инвариант анти-утечки:** ни один аптамерный кластер не присутствует
  одновременно в train и test кластерного разбиения.
- **Детерминизм:** при фиксированном seed все артефакты воспроизводимы.
