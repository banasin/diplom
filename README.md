# Дипломная работа: предсказание аффинности аптамер–мишень

Two-tower нейросетевая модель предсказания аффинности связывания пары
«аптамер–белок» (log-Kd) со сравнением против классического бейзлайна.
Подробный план — в [`plan_diploma.md`](plan_diploma.md).

## Структура репозитория

```
diplom/
├── plan_diploma.md      # план работы (Часть 1 детально)
├── README.md
├── requirements.txt
├── .gitignore
│
├── data/                # ДАННЫЕ НЕ КОММИТЯТСЯ В GIT (см. .gitignore)
│   └── dataset.xlsx     #   исходный агрегированный датасет (6 баз)
│                        #   сюда же пишутся очищенные таблицы
│
├── notebooks/           # разведочный анализ, черновые эксперименты
├── configs/             # конфиги экспериментов (yaml/json)
│
├── src/                 # переиспользуемый код (в git)
│   ├── data/            #   сбор, чистка, дедупликация, разбиение train/test
│   ├── features/        #   кодирование аптамеров (k-меры) и белков (ESM-2)
│   ├── models/          #   бейзлайн (бустинг) и two-tower сеть
│   └── evaluation/      #   метрики (RMSE, MAE, корреляция), протокол оценки
│
├── models/              # ОБУЧЕННЫЕ ВЕСА НЕ КОММИТЯТСЯ В GIT
└── results/
    ├── figures/         #   графики (не коммитятся)
    └── metrics/         #   таблицы метрик (не коммитятся)
```

## Что попадает в git, а что — нет

**В git:** код (`src/`), ноутбуки, конфиги, планы, `requirements.txt`.
**НЕ в git** (игнорируется): содержимое `data/`, `models/`, `results/`,
любые `*.csv/*.parquet/*.pt/*.npy`, виртуальные окружения, кэши.

Так репозиторий остаётся лёгким, а большие бинарники не создают
конфликтов и не упираются в лимит GitHub (100 МБ на файл).

## Быстрый старт

```bash
python -m venv .venv
source .venv/Scripts/activate      # Windows (Git Bash); PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Работа с git без конфликтов

```bash
git pull            # перед началом работы — подтянуть изменения
# ... работа ...
git add <файлы>     # добавлять осознанно; git status покажет, что нового
git commit -m "..."
git push
```

Если `git status` показывает большой файл данных — значит он не попал под
`.gitignore`; **не коммить его**, а поправь `.gitignore`.
