# Спецификация реализации: Часть 4 (структурный уровень и интерпретируемость)

**Дата:** 2026-08-16
**Проект:** Предсказание аффинности аптамер–мишень. Часть 4 — структурный уровень
признаков (вторичная структура) как третий тип кодирования; механистическая
интерпретация вклада признаков; сопоставление с интерпретируемой MNA/N-граммной
SAR-моделью (OLMPASS/MultiPASS).
**Основа:** Части 1–3 завершены (парные модели аффинности, ESM-2, честный сплит,
анализ спектра). Часть 4 переиспользует их модули.

## Контекст

Оригинальное исследование (статья «Predicting the activity spectrum of aptamers
from substructural fragments: multi-class SAR models using MNA and N-gram
descriptors», те же 4745 пар) построило мульти-классовые SAR-модели предсказания
**спектра мишеней** DNA/RNA-аптамеров на дескрипторах **MNA** (атом-центрированные)
и **N-грамм** алгоритмом MultiPASS, при порогах 150нМ/500нМ. Held-out
per-target IAP = 0.67–0.95. Наши нейросетевые модели аффинности (Части 1–3) на
held-out аптамерах спектр мишеней **не разрешают** (retrieval на уровне случайного,
Часть 3). Часть 4 вводит структурный уровень признаков, механистически
интерпретирует нашу модель и строго сопоставляет её с интерпретируемыми
MNA/N-граммными моделями.

**Ограничение:** OLMPASS/MultiPASS — проприетарное ПО (активация, Windows-exe),
запустить/переобучить нельзя. Модели лучших предикторов лежат в `best_models/`
(вне git — крупные бинарники + рукопись). Сопоставление опирается на **выходные
файлы** моделей (`*_targets.csv` с per-target IAP и идентификаторами) и статью.

## Гипотезы

- **H7 (структура):** структурные признаки вторичной структуры улучшают
  предсказание аффинности сверх последовательности (k-меры) и ESM-2.
- **H8 (интерпретируемость/сопоставление):** интерпретируемые MNA/N-граммные
  SAR-модели достигают более высокого per-target качества на held-out, чем наша
  нейросетевая модель аффинности на общей площадке; важные сиквенс-мотивы
  (k-меры/N-граммы) механистически интерпретируемы.

## Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Вторичная структура | Nussinov (макс. комплементарных пар), чистый Python, без зависимостей |
| Интерпретация | SHAP (TreeExplainer) по XGBoost на объединённых признаках |
| Сопоставление с MNA/N-gram | Из выходных файлов (`*_targets.csv`: per-target IAP + идентификаторы) + статья; OLMPASS не запускается |
| Общая площадка сравнения | per-target AUC (наш) vs per-target IAP (OLMPASS) на пересечении мишеней |
| Оговорённые значения | Оставляем (как Части 2–3) |
| Сплит | Честный кластерный по аптамеру (Часть 1) |
| Проприетарные файлы/рукопись | `best_models/`, `Article.docx`, описания OLMPASS — в `.gitignore`, вне GitHub |
| Компьют | Windows, RTX 4070 (CUDA) |

## Модульная структура

Переиспускаемое без изменений: `aptamer.py`, `protein.py`/`protein_seqs.py`
(ESM-2), `cluster.py`, `split.py`, `baseline.py`, `twotower.py`, `metrics.py`,
`evaluation/ranking.py`, `config.py`.

### 1. `src/features/structure.py` — вторичная структура (Nussinov)

- `nussinov(seq) -> str` — точечно-скобочная структура по алгоритму Nussinov
  (максимизация числа комплементарных пар: A–T/U, G–C, с минимальным размером
  петли; U≡T нормализация).
- `structure_features(seq) -> np.ndarray` — вектор структурных признаков:
  доля спаренных нуклеотидов, число пар, число шпилек (hairpin-петель), макс.
  длина непрерывного стебля, простая оценка «энергии» (−число пар / длину).
- Детерминизм; чистый Python.

### 2. `src/data/olmpass.py` — парсинг выходов MNA/N-граммных моделей

- `parse_targets_csv(path) -> pd.DataFrame` — разбор `*_targets.csv`
  (разделитель `;`, десятичная запятая): колонки `No, N, IAP, Activity Type,
  Identifier, Type Target, Target organism`. IAP → float.
- `load_olmpass_iap(best_models_dir) -> pd.DataFrame` — собрать все `*_targets.csv`
  (по порогам 150нМ/500нМ, DNA/RNA, MNA/Ngram) в длинную таблицу с колонками
  `threshold, aptamer_type, descriptor, target_identifier, iap, n_actives`.

### 3. `src/interpretability.py` — вклад признаков (SHAP)

- `shap_feature_importance(model, X, feature_names, top_k=30) -> pd.DataFrame` —
  средний |SHAP| по признакам (TreeExplainer), топ-k с именами (k-меры/структура/
  ESM-размерности). Возвращает таблицу `feature, mean_abs_shap, group`.
- Группировка признаков по типу (kmer / structure / esm) для сводного вклада.

### 4. Общая площадка для H8 — per-target качество нашей модели

- `src/evaluation/per_target.py` — `per_target_auc(pairs_test, predict_fn,
  aptamer_feats, target_emb) -> dict[str, float]`: для каждой мишени ранжируем
  test-аптамеры по предсказанной силе связывания (−log-Kd), AUC связывателей
  против остальных (нужно ≥1 позитив и ≥1 негатив). Транспонирование Части 3,
  напрямую сравнимо с IAP.
  *(Замечание: наш «негатив» — аптамеры без измеренной пары к мишени, т.е.
  предположительные не-связыватели; отметить в отчёте как приближение.)*

### 5. `src/run_part4.py` — оркестратор

- Белковые пары → кластерный сплит → ESM-2 (кэш).
- **H7:** обучить XGBoost на `[k-меры | ESM-2]` и на `[k-меры | структура | ESM-2]`;
  сравнить метрики (RMSE/Pearson/R²) на честном сплите → улучшает ли структура.
- **Интерпретация:** SHAP по расширенной модели → топ k-меров/структурных
  признаков; сводный вклад по группам.
- **H8:** per-target AUC нашей модели на test-мишенях; parse OLMPASS IAP;
  сопоставить на пересечении мишеней (идентификаторы) → таблица + scatter
  IAP-vs-AUC; вывод о превосходстве интерпретируемых моделей на спектре.
- Пишет `results/metrics/part4_h7.csv`, `part4_shap.csv`, `part4_h8.csv` и
  графики.

### Конфигурация

`configs/part4.yaml`: seed, порог кластеризации, доля теста, k, имя ESM-модели,
гиперпараметры XGBoost, путь `best_models/`, top_k для SHAP, порог силы связывания.

## Поток данных

```
dataset_protein.parquet
   └─ build_pairs(keep_qualified) → cluster+split
белки: ESM-2 (кэш); аптамеры: k-меры + structure.py (Nussinov)
   ├─ H7: XGBoost [kmer|esm] vs [kmer|structure|esm] → метрики
   ├─ SHAP: топ признаков (interpretability.py)
   └─ H8: per_target_auc (наш) ↔ olmpass.py (IAP) на общих мишенях
   └─ таблицы + графики
```

## Тестирование

- Юнит-тесты:
  - `nussinov` на известных последовательностях (комплементарная → полностью
    спарена; неспособная спариться → «.....»); `structure_features` (формы,
    доля спаренных);
  - `parse_targets_csv` на маленьком синтетическом CSV (`;`, запятая-десятичная);
  - `shap_feature_importance` на игрушечной XGBoost-модели (форма/имена);
  - `per_target_auc` на синтетике (идеальное ранжирование → AUC=1).
- Инвариант честности: per-target AUC и обучение — на честном сплите (пары
  test-аптамеров не в train).
- Детерминизм при seed. Артефакты/проприетарные файлы вне git.
